МАСТЕР-ЧЕКПОИНТ ПРОЕКТА YOUNG-STARS (ХОККЕЙ)

1. ОБЩАЯ ИНФОРМАЦИЯ
Стек: Vanilla JS, HTML, CSS, Supabase, Chart.js, jsPDF.
Архитектура: Модульная (30+ файлов).
Хранение: Supabase + LocalStorage.
Git: коммит и пуш выполняет пользователь локально (у ИИ нет доступа к репозиторию).

3. ПОДРОБНОЕ ОПИСАНИЕ МОДУЛЕЙ
- 01-config.js: Ключи Supabase, глобальный DB, константы. PIN-константы (PIN_LENGTH=4, PIN_ATTEMPTS_MAX=3, PIN_BLOCK_SECONDS=60, PIN_STORAGE_KEY='akbars_pin_attempts'), generatePin().
- 02-utils.js: Модалки, даты, возраст.
- 03-sync.js: Авторизация, синхронизация, isPlayerMode.
  * Вход тренера: doLogin — email+пароль. Регистрация через UI отключена.
  * Вход игрока: playerAuthStepFio -> выбор при совпадениях -> doPlayerPinLogin.
  * getPinAttempts/savePinAttempts/clearPinAttempts/playerAuthReset.
  * switchAuthTab/setAuthLoading: только login/player, null-checks.
  * onAuthorized: вызывает bindNavigation().
  * packPlayersForCloud: не перезаписывает currentSeason тренера из режима игрока (coach_default_season).
- 04-ui.js: Навигация, уведомления, рендер игроков, PIN-администрирование.
  * bindNavigation(): onclick на всех кнопках [data-screen]. Вызывается из DOMContentLoaded и onAuthorized.
  * showScreen: в try/catch; при isPlayerMode принудительно 'player'.
  * openPlayerPinsModal, generatePinsForAll, regeneratePlayerPin, syncPinsAcrossSeasons (personPinKey: ФИО+год рождения).
  * Гварды isPlayerMode в addPlayerSubgroup/renamePlayerSubgroup/deletePlayerSubgroup/renderDashboard.
- 05a-player-core.js: Карточка игрока.
  * __ensurePlayerPin (accessPin:'' по умолчанию), personPinKey(p), автогенерация PIN при создании, PIN в паспорте у тренера.
- 05b-player-calendar.js: Календарь игрока. Редактирование только «Самостоятельная» (__canPlayerEditBlock). Кнопка "Текущий месяц" использует стандартный класс .btn.
- 09-excel.js: Excel/JSON/CSV. Автогенерация PIN при импорте Excel/CSV. exportPlayerPinsExcel. __ensurePlayerPin при импорте JSON.
- 10-init.js: Точка входа.
- 11-dashboard-calendar.js: Хелперы для календаря тренера (черновики, complexItems).
- 12-coach-report.js: Отчёт тренера. Все KPI и кнопки экспорта переведены на стандартные .btn (без .btn-red).
- 13-seasons.js: switchSeason для игрока — только карточка (поиск по ФИО). Гварды isPlayerMode во всех функциях редактирования сезонов. Кнопки в модалках используют класс .btn (без ghost/red, кроме удаления).
- 40-coach-grid.js: Месячная сетка тренера. Кнопка "Текущий месяц" использует стандартный класс .btn (без ghost).
- 41-48: Модули календаря тренера (модалки, факты, сессии).
- 50-player-skills.js, 51-player-stats.js: карточка (только тренер).
- 52-player-tests.js: тесты. Игрок — просмотр. Гварды isPlayerMode: renameTestColumn, resetTestColumns, updateTest, addTest, removeTest.
- 53-player-radars.js: радары.

4. ТЕХНИЧЕСКИЕ ПРАВИЛА
- Supabase RLS: "Allow anon read" (SELECT, using(true)) на coach_data. ID тренера — localStorage('coach_id'). «Сезон тренера» — localStorage('coach_default_season').
- Аутентификация игрока: ФИО -> выбор -> PIN, p.accessPin.
- PIN: 4 цифры (generatePin через crypto.getRandomValues), хранится открыто (см. оговорку).
- Rate-limit PIN: 3 попытки -> блок 60 сек.
- Игрок без PIN (accessPin='') -> «Доступ не настроен. Обратитесь к тренеру.».
- Синхронизация PIN между сезонами по personPinKey (ФИО+год рождения).
- Навигация: onclick прямо в HTML + bindNavigation() из JS (двойная защита). onAuthorized вызывает bindNavigation.
- Гвард isPlayerMode в начале любой функции изменения (кроме «Самостоятельных» в 05b).
- Функции для onclick — глобальные.
- Сброс кэша: Ctrl+F5 после обновления файлов.
- Git: коммит/пуш — на стороне пользователя. Перед `git add .` обязательно `git status`; мусор исключать через .gitignore.
- Дизайн: сдержанный стиль «белый + тёмно-зелёная рамка». Никаких красных кнопок, кроме «Удалить», «Выйти», «Очистить локально» и семантических статусов. Все экспорты, импорты и отчеты оформлены как обычные `.btn` или `.btn-ghost` (если это кнопки второго плана). Убрано «1956» из логотипа в шапке.

Оговорка про безопасность PIN:
- От «сосед набрал мою фамилию» — защищает (нужен PIN).
- От «подобрать перебором» — защищает rate-limit.
- НЕ защищает от пользователя с F12 (coach_data читается анонимно). Для полной защиты — Вариант Б (Supabase Auth на каждого игрока).

5. ПРАВИЛА РАБОТЫ
1. Пользователь НЕ пишет код. Выдавай ПОЛНЫЙ код файла целиком.
2. Не проси присылать "кусочки", если нужен файл — проси прислать файл.
3. Скриншоты для редизайна присылать только обрезанные (1 скрин = 1 задача).
4. ВАЖНО: После каждого выполненного шага ИИ обязан выдавать обновлённый текст МАСТЕР-ЧЕКПОИНТА.
5. ВАЖНО: МАСТЕР-ЧЕКПОИНТ всегда присылать в виде файла TXT (готового к прямой замене CHECKPOINT.txt, кодировка UTF-8). Содержимое блока = полное содержимое файла.
6. ВАЖНО: Любой изменённый модуль (js, html, css) ВСЕГДА выдавать ПОЛНОСТЬЮ (весь файл целиком), а не патчем/фрагментом.
7. ВАЖНО: Если в ответе несколько файлов — каждый файл оформлять отдельным заголовком с явной нумерацией и именем: «Файл 1: 04-ui.js», «Файл 2: 03-sync.js» и т.д.
8. ВАЖНО: ИИ не выполняет git-коммиты и не пушит — у него нет доступа к репозиторию пользователя.
