МАСТЕР-ЧЕКПОИНТ ПРОЕКТА YOUNG-STARS (ХОККЕЙ)

1. ОБЩАЯ ИНФОРМАЦИЯ
Стек: Vanilla JS, HTML, CSS, Supabase, Chart.js, jsPDF.
Архитектура: Модульная (30+ файлов).
Хранение: Supabase + LocalStorage.
Git: коммит и пуш выполняет пользователь локально (у ИИ нет доступа к репозиторию).

3. ПОДРОБНОЕ ОПИСАНИЕ МОДУЛЕЙ
- 01-config.js: Ключи Supabase, глобальный DB, константы. PIN-константы, generatePin().
- 02-utils.js: Модалки, даты, возраст.
- 03-sync.js: Авторизация, синхронизация, isPlayerMode.
  * Вход тренера: doLogin — email+пароль. Регистрация отключена.
  * Вход игрока: playerAuthStepFio -> выбор -> doPlayerPinLogin.
  * getPinAttempts/savePinAttempts/clearPinAttempts/playerAuthReset.
  * setupRealtimeSync(): Подписка на Supabase Realtime. Мгновенно вызывает pullFromCloud() и перерисовывает UI.
  * parseTime() в pullFromCloud().
  * packPlayersForCloud: не перезаписывает currentSeason тренера из режима игрока.
- 04-ui.js: Навигация, уведомления, рендер игроков, PIN-администрирование.
  * bindNavigation(): onclick на кнопках [data-screen].
  * openPlayerPinsModal, generatePinsForAll, regeneratePlayerPin, syncPinsAcrossSeasons.
- 05a-player-core.js: Карточка игрока.
  * __ensurePlayerPin, personPinKey, автогенерация PIN.
  * saveNewPlayer: обновляет DB.seasons[currentSeason] и touchMeta('players').
- 05b-player-calendar.js: Календарь игрока.
- 09-excel.js: Excel/JSON/CSV. Обновляют DB.seasons и touchMeta('players').
- 10-init.js: Точка входа.
- 11-dashboard-calendar.js: Хелперы календаря тренера.
- 12-coach-report.js: Отчёт тренера.
- 13-seasons.js: switchSeason для игрока, createSeason, copyPlayerForNewSeason (структура навыков копируется из текущего игрока).
- 40-coach-grid.js: Месячная сетка тренера.
- 41-48: Модули календаря тренера.
- 50-player-skills.js: Вкладка «Навыки» в карточке.
  * **ИСПРАВЛЕН БАГ С РАСИНХРОНОМ:** При редактировании, добавлении или удалении навыка структура синхронизируется по всем игрокам текущего сезона (через syncTechStructure и syncOtherStructure). Это исключает дубли и сбивание оценок.
  * Удаление затрагивает ТОЛЬКО текущий сезон. Архивные сезоны не изменяются.
- 51-player-stats.js: карточка.
- 52-player-tests.js: тесты. Гварды isPlayerMode.
- 53-player-radars.js: радары.

4. ТЕХНИЧЕСКИЕ ПРАВИЛА
- Supabase RLS: "Allow anon read" на coach_data.
- Realtime: Включен через `sb.channel().on('postgres_changes')`.
- PIN: 4 цифры, хранится открыто. Rate-limit: 3 попытки -> блок 60 сек.
- Навигация: onclick прямо в HTML + bindNavigation().
- Гвард isPlayerMode в начале любой функции изменения.
- Функции для onclick — глобальные.
- Сброс кэша: Ctrl+F5.
- Git: коммит/пуш — на стороне пользователя. `git status` -> `git add .` -> `git commit` -> `git push`.
- Дизайн: сдержанный стиль «белый + тёмно-зелёная рамка». Убрано «1956». Дни недели в календаре — с зелёной рамкой.
- Синхронизация структуры навыков: при изменении навыка у одного игрока он обновляется у всех через `syncTechStructure()` и `syncOtherStructure()`. Сравнение идёт по связке "раздел + название".

5. ПРАВИЛА РАБОТЫ
1. Пользователь НЕ пишет код. Выдавай ПОЛНЫЙ код файла целиком.
2. Не проси присылать "кусочки", если нужен файл — проси прислать файл.
3. Скриншоты для редизайна присылать только обрезанные (1 скрин = 1 задача).
4. ВАЖНО: После каждого выполненного шага ИИ обязан выдавать обновлённый текст МАСТЕР-ЧЕКПОИНТА.
5. ВАЖНО: МАСТЕР-ЧЕКПОИНТ всегда присылать в виде файла TXT (готового к прямой замене CHECKPOINT.txt, кодировка UTF-8). Содержимое блока = полное содержимое файла.
6. ВАЖНО: Любой изменённый модуль (js, html, css) ВСЕГДА выдавать ПОЛНОСТЬЮ (весь файл целиком), а не патчем/фрагментом.
7. ВАЖНО: Если в ответе несколько файлов — каждый файл оформлять отдельным заголовком с явной нумерацией и именем: «Файл 1: 04-ui.js», «Файл 2: 03-sync.js» и т.д.
8. ВАЖНО: ИИ не выполняет git-коммиты и не пушит — у него нет доступа к репозиторию пользователя.
