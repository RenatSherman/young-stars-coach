МАСТЕР-ЧЕКПОИНТ ПРОЕКТА YOUNG-STARS (ХОККЕЙ)

1. ОБЩАЯ ИНФОРМАЦИЯ
Стек: Vanilla JS, HTML, CSS, Supabase, Chart.js, jsPDF.
Архитектура: Модульная (30+ файлов).
Хранение: Supabase + LocalStorage.

3. ПОДРОБНОЕ ОПИСАНИЕ МОДУЛЕЙ
- 01-config.js: Ключи Supabase, глобальный DB, константы. PIN-константы (PIN_LENGTH=4, PIN_ATTEMPTS_MAX=3, PIN_BLOCK_SECONDS=60, PIN_STORAGE_KEY='akbars_pin_attempts'), generatePin().
- 02-utils.js: Модалки, даты, возраст.
- 03-sync.js: Авторизация, синхронизация, isPlayerMode.
  * Вход тренера: doLogin — email+пароль. Регистрация через UI отключена (аккаунт тренера один, регистрацию не показываем, чтобы игроки не создавали лишние аккаунты).
  * Вход игрока: playerAuthStepFio -> выбор при совпадениях -> doPlayerPinLogin.
  * Вспомогательные: getPinAttempts/savePinAttempts/clearPinAttempts/playerAuthReset.
  * switchAuthTab: только login/player, безопасно при отсутствующих элементах (null-checks).
  * setAuthLoading: без register, безопасно при отсутствующих элементах.
  * onAuthorized: вызывает bindNavigation() из 04-ui.js для перепривязки меню после входа.
  * packPlayersForCloud: в режиме игрока не перезаписывает currentSeason тренера (coach_default_season).
- 04-ui.js: Навигация, уведомления, рендер игроков, PIN-администрирование.
  * bindNavigation(): назначает onclick каждой кнопке [data-screen] в nav. Вызывается из DOMContentLoaded и из onAuthorized (двойная защита).
  * showScreen: обёрнут в try/catch, устойчив к падениям рендера. При isPlayerMode принудительно 'player'.
  * PIN-функции: openPlayerPinsModal, generatePinsForAll, regeneratePlayerPin, syncPinsAcrossSeasons (по personPinKey: ФИО+год рождения).
  * Гварды isPlayerMode в addPlayerSubgroup/renamePlayerSubgroup/deletePlayerSubgroup/renderDashboard.
- 05a-player-core.js: Карточка игрока.
  * Миграция: __ensurePlayerPin (accessPin:'' по умолчанию).
  * personPinKey(p): ключ ФИО+год рождения для дедупликации и синхронизации PIN.
  * saveNewPlayer: автогенерация PIN.
  * renderPlayerCard: PIN показан только тренеру (в паспорте, с кнопкой «Сбросить/Создать»).
- 05b-player-calendar.js: Календарь игрока. Игрок редактирует ТОЛЬКО «Самостоятельная» (хелпер __canPlayerEditBlock).
- 09-excel.js: Excel/JSON/CSV.
  * importPlayerFromExcel: автогенерация PIN, вывод PIN в отчёте.
  * importCSVFile: автогенерация accessPin каждому новому игроку.
  * exportPlayerPinsExcel: выгрузка списка PIN в xlsx.
  * importData(JSON): прогоняет __ensurePlayerPin.
- 10-init.js: Точка входа.
- 13-seasons.js: Ядро сезонов + UI. switchSeason для игрока — только карточка (поиск по ФИО в новом сезоне). Гварды isPlayerMode во всех функциях редактирования сезонов.
- 40-48: Модули календаря тренера.
- 50-player-skills.js, 51-player-stats.js: карточка игрока (только тренер).
- 52-player-tests.js: тесты. Игрок — просмотр. Гварды isPlayerMode: renameTestColumn, resetTestColumns, updateTest, addTest, removeTest.
- 53-player-radars.js: радары.

4. ТЕХНИЧЕСКИЕ ПРАВИЛА
- Supabase RLS: "Allow anon read" (SELECT, using(true)) на coach_data. ID тренера — localStorage('coach_id'). «Сезон тренера» — localStorage('coach_default_season').
- Аутентификация игрока: многошаговая (ФИО -> выбор -> PIN), p.accessPin.
- PIN: 4 цифры, generatePin() через crypto.getRandomValues. Хранится в открытом виде (см. оговорку).
- Rate-limit PIN: 3 попытки -> блок 60 сек (localStorage 'akbars_pin_attempts').
- Игрок без PIN (accessPin='') -> «Доступ не настроен. Обратитесь к тренеру.».
- Синхронизация PIN между сезонами: по personPinKey (ФИО+год рождения), syncPinsAcrossSeasons.
- Навигация: кнопки nav имеют И onclick в HTML (гарантирует работу даже при сбое DOMContentLoaded) И bindNavigation() из JS (перепривязка после входа). Двойная защита.
- Гвард isPlayerMode в начале любой функции изменения (кроме «Самостоятельных» в 05b).
- Функции для onclick — глобальные.
- Сброс кэша: Ctrl+F5.

Оговорка про безопасность PIN:
- От «сосед набрал мою фамилию» — защищает (нужен PIN).
- От «подобрать перебором» — защищает rate-limit.
- НЕ защищает от пользователя с F12, т.к. coach_data читается анонимно. Для полной защиты нужен Supabase Auth (Вариант Б).

5. ПРАВИЛА РАБОТЫ
1. Пользователь НЕ пишет код. Выдавай ПОЛНЫЙ код файла целиком.
2. Не проси присылать "кусочки", если нужен файл — проси прислать файл.
3. Скриншоты для редизайна присылать только обрезанные (1 скрин = 1 задача).
4. ВАЖНО: После каждого выполненного шага ИИ обязан выдавать обновлённый текст МАСТЕР-ЧЕКПОИНТА.
5. ВАЖНО: МАСТЕР-ЧЕКПОИНТ всегда присылать в виде файла TXT (готового к прямой замене CHECKPOINT.txt, кодировка UTF-8). Содержимое блока = полное содержимое файла.
6. ВАЖНО: Любой изменённый модуль (js, html, css) ВСЕГДА выдавать ПОЛНОСТЬЮ (весь файл целиком), а не патчем/фрагментом. Пользователь заменяет файл целиком.
7. ВАЖНО: Если в ответе несколько файлов — каждый файл оформлять отдельным заголовком с явной нумерацией и именем: «Файл 1: 04-ui.js», «Файл 2: 03-sync.js» и т.д. Пользователь должен точно понимать, сколько файлов пришло, какие именно и в каком порядке их сохранять.
