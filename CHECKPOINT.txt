МАСТЕР-ЧЕКПОИНТ ПРОЕКТА YOUNG-STARS (ХОККЕЙ)

1. ОБЩАЯ ИНФОРМАЦИЯ
Стек: Vanilla JS, HTML, CSS, Supabase, Chart.js, jsPDF.
Архитектура: Модульная (30+ файлов).
Хранение: Supabase + LocalStorage.
Git: коммит и пуш выполняет пользователь локально (у ИИ нет доступа к репозиторию).

- 12-coach-report.js: Отчёт тренера. Все KPI и кнопки переведены на .btn.
- 13-seasons.js: switchSeason для игрока — только карточка. Гварды isPlayerMode.

- 53-player-radars.js: радары.

4. ТЕХНИЧЕСКИЕ ПРАВИЛА
- Supabase RLS: "Allow anon read" на coach_data. ID тренера — localStorage('coach_id'). «Сезон тренера» — localStorage('coach_default_season').
- Realtime: Включен через `sb.channel().on('postgres_changes')`.
- Аутентификация игрока: ФИО -> выбор -> PIN, p.accessPin.
- PIN: 4 цифры, хранится открыто (см. оговорку). Rate-limit: 3 попытки -> блок 60 сек.
- Синхронизация PIN между сезонами по personPinKey (ФИО+год рождения).
- Навигация: onclick прямо в HTML + bindNavigation().
- Гвард isPlayerMode в начале любой функции изменения.
- Функции для onclick — глобальные.
- Сброс кэша: Ctrl+F5.
- Git: коммит/пуш — на стороне пользователя. `git status` -> `git add .` -> `git commit` -> `git push`. Если VS Code просит сохранить файл — "Don't Save".
- Дизайн: сдержанный стиль «белый + тёмно-зелёная рамка». Убрано «1956». Дни недели в календаре — с зелёной рамкой.

Оговорка про безопасность PIN:
- От «сосед набрал мою фамилию» — защищает (нужен PIN).
- НЕ защищает от пользователя с F12 (coach_data читается анонимно). Для полной защиты — Вариант Б.

5. ПРАВИЛА РАБОТЫ
1. Пользователь НЕ пишет код. Выдавай ПОЛНЫЙ код файла целиком.
2. Не проси присылать "кусочки", если нужен файл — проси прислать файл.
3. Скриншоты для редизайна присылать только обрезанные (1 скрин = 1 задача).
4. ВАЖНО: После каждого выполненного шага ИИ обязан выдавать обновлённый текст МАСТЕР-ЧЕКПОИНТА.
5. ВАЖНО: МАСТЕР-ЧЕКПОИНТ всегда присылать в виде файла TXT (готового к прямой замене CHECKPOINT.txt, кодировка UTF-8). Содержимое блока = полное содержимое файла.
6. ВАЖНО: Любой изменённый модуль (js, html, css) ВСЕГДА выдавать ПОЛНОСТЬЮ (весь файл целиком), а не патчем/фрагментом.
7. ВАЖНО: Если в ответе несколько файлов — каждый файл оформлять отдельным заголовком с явной нумерацией и именем: «Файл 1: 04-ui.js», «Файл 2: 03-sync.js» и т.д.
8. ВАЖНО: ИИ не выполняет git-коммиты и не пушит — у него нет доступа к репозиторию пользователя.
