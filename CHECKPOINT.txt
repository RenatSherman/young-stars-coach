МАСТЕР-ЧЕКПОИНТ ПРОЕКТА YOUNG-STARS (ХОККЕЙ)

1. ОБЩАЯ ИНФОРМАЦИЯ
Стек: Vanilla JS, HTML, CSS, Supabase, Chart.js, jsPDF.
Архитектура: Модульная (30+ файлов).
Хранение: Supabase + LocalStorage.
Git: коммит и пуш выполняет пользователь локально (у ИИ нет доступа к репозиторию).

2. ПОРЯДОК ПОДКЛЮЧЕНИЯ СКРИПТОВ В index.html
01-config.js -> 02-utils.js -> 03-sync.js -> 04-ui.js -> 05a-player-core.js -> 05b-player-calendar.js -> 06-plan.js -> 06b-report.js -> 07-calendar.js -> 08-pdf.js -> 09-excel.js -> 10-init.js -> 11-dashboard-calendar.js -> 12-coach-report.js -> 13-seasons.js -> 40-coach-grid.js -> 41-coach-day-modal.js -> 42-coach-fact-editor.js -> 43-coach-session-editor.js -> 44-coach-complex-picker.js -> 45-coach-repeat-block.js -> 46-coach-players-picker.js -> 47-coach-delete.js -> 48-coach-templates.js -> 50-player-skills.js -> 51-player-stats.js -> 52-player-tests.js -> 53-player-radars.js

3. ПОДРОБНОЕ ОПИСАНИЕ МОДУЛЕЙ
- 01-config.js: Ключи Supabase, глобальный DB, константы. PIN-константы, generatePin().
- 02-utils.js: Модалки, даты, возраст.
- 03-sync.js: Авторизация, синхронизация, isPlayerMode.
  * Вход тренера: doLogin. Вход игрока: playerAuthStepFio -> doPlayerPinLogin.
  * setupRealtimeSync(): Подписка на Supabase Realtime (pullFromCloud(true)).
  * Исправлен баг перезаписи времени при пуле.
- 04-ui.js: Навигация, уведомления, рендер игроков, PIN-администрирование.
  * bindNavigation(): onclick на кнопках [data-screen].
  * openPlayerPinsModal, generatePinsForAll, regeneratePlayerPin.
- 05a-player-core.js: Карточка игрока (сохранение, удаление, PIN в паспорте).
- 05b-player-calendar.js: Календарь игрока. Кнопка "Текущий месяц" — класс .btn.
- 09-excel.js: Excel/JSON/CSV. Обновляют DB.seasons и touchMeta('players').
- 10-init.js: Точка входа.
- 11-dashboard-calendar.js: Хелперы календаря тренера.
- 12-coach-report.js: Отчёт тренера.
- 13-seasons.js: switchSeason, createSeason, copyPlayerForNewSeason.
- 40-coach-grid.js: Месячная сетка тренера.
- 41-48: Модули календаря тренера (модалки, факты, сессии).
- 50-player-skills.js: Вкладка «Навыки».
  * syncTechStructure и syncOtherStructure (синхронизация при редактировании).
  * touchMeta в updateTech и updateOther.
  * **forceSyncAllPlayersSkills():** принудительно выравнивает навыки у всех игроков сезона (вызывается из «Данные»).
- 51-player-stats.js: карточка.
- 52-player-tests.js: тесты. Гварды isPlayerMode.
- 53-player-radars.js: радары.

4. ТЕХНИЧЕСКИЕ ПРАВИЛА
- Supabase RLS: "Allow anon read" на coach_data.
- Realtime: Обязательно включить для таблицы `coach_data`.
- PIN: 4 цифры. Rate-limit: 3 попытки -> блок 60 сек.
- Навигация: onclick прямо в HTML + bindNavigation().
- Гвард isPlayerMode в начале любой функции изменения.
- Сброс кэша: Ctrl+F5.
- Git: коммит/пуш — на стороне пользователя. `git status` -> `git add .` -> `git commit` -> `git push`.
- Дизайн: сдержанный стиль «белый + тёмно-зелёная рамка». Убрано «1956». Дни недели в календаре — с зелёной рамкой.
- Синхронизация: любой `saveDB()` должен сопровождаться `touchMeta('players')`.

5. ПРАВИЛА РАБОТЫ
1. Пользователь НЕ пишет код. Выдавай ПОЛНЫЙ код файла целиком.
2. Не проси присылать "кусочки", если нужен файл — проси прислать файл.
3. Скриншоты для редизайна присылать только обрезанные (1 скрин = 1 задача).
4. ВАЖНО: После каждого выполненного шага ИИ обязан выдавать обновлённый текст МАСТЕР-ЧЕКПОИНТА.
5. ВАЖНО: МАСТЕР-ЧЕКПОИНТ всегда присылать в виде файла TXT (готового к прямой замене CHECKPOINT.txt, кодировка UTF-8).
6. ВАЖНО: Любой изменённый модуль (js, html, css) ВСЕГДА выдавать ПОЛНОСТЬЮ (весь файл целиком).
7. ВАЖНО: Если в ответе несколько файлов — каждый файл оформлять отдельным заголовком с нумерацией.
8. ВАЖНО: ИИ не выполняет git-коммиты и не пушит.
